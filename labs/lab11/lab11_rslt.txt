Lab #11 – Raw ADC to Celsius and 32-bit IEEE 754 Float Conversion
====================================================================

The four readings used are:

1) Raw ADC: 0x386  | Temperature shown: 14.96 degC
2) Raw ADC: 0x389  | Temperature shown: 13.56 degC
3) Raw ADC: 0x388  | Temperature shown: 14.03 degC
4) Raw ADC: 0x380  | Temperature shown: 17.77 degC

Assumptions and formulas used
-----------------------------
1. The ADC on the RP2040 is 12-bit, so its range is 0 to 4095.
2. ADC voltage conversion:
      V = (raw_ADC / 4096) × 3.3
3. Temperature conversion for the RP2040 internal temperature sensor:
      T = 27 - (V - 0.706) / 0.001721
4. IEEE 754 single-precision float format uses:
      - 1 sign bit
      - 8 exponent bits
      - 23 fraction bits

Important note
--------------
The raw ADC values convert to temperatures very close to the printed values.
Small differences happen because the displayed temperature is rounded to 2
decimal places, while the actual calculation contains more digits.

READING 1
====================================================================


A. Raw ADC hexadecimal to decimal
---------------------------------
Raw ADC = 0x386

Convert hexadecimal to decimal:
0x386 = 902 decimal

Expanded:
      3×16^2 + 8×16^1 + 6×16^0
      = 902

B. Convert raw ADC value to voltage
-----------------------------------
Formula:
      V = (raw_ADC / 4096) × 3.3

Substitute raw_ADC = 902:
      V = (902 / 4096) × 3.3
      V = 0.220214844 × 3.3
      V = 0.726708984 V

C. Convert voltage to temperature
---------------------------------
Formula:
      T = 27 - (V - 0.706) / 0.001721

Substitute V = 0.726708984:
      T = 27 - (0.726708984 - 0.706) / 0.001721
      T = 27 - (0.020708984) / 0.001721
      T = 27 - 12.033111200
      T = 14.966888800 °C

Rounded to 2 decimal places:
      T ≈ 14.96 °C

D. Convert the decimal temperature to IEEE 754 single precision
---------------------------------------------------------------
Temperature to encode:
      14.96 decimal

Step 1: Write the decimal number as integer part + fractional part
      14.96 = 14 + 0.960000000000

Step 2: Convert the integer part to binary
      14 decimal = 1110 binary

Step 3: Convert the fractional part to binary by repeated multiplication by 2
      Step  1: 0.960000000000 × 2 = 1.920000000000  -> bit = 1, new fraction = 0.920000000000
      Step  2: 0.920000000000 × 2 = 1.840000000000  -> bit = 1, new fraction = 0.840000000000
      Step  3: 0.840000000000 × 2 = 1.680000000000  -> bit = 1, new fraction = 0.680000000000
      Step  4: 0.680000000000 × 2 = 1.360000000000  -> bit = 1, new fraction = 0.360000000000
      Step  5: 0.360000000000 × 2 = 0.720000000000  -> bit = 0, new fraction = 0.720000000000
      Step  6: 0.720000000000 × 2 = 1.440000000000  -> bit = 1, new fraction = 0.440000000000
      Step  7: 0.440000000000 × 2 = 0.880000000000  -> bit = 0, new fraction = 0.880000000000
      Step  8: 0.880000000000 × 2 = 1.760000000000  -> bit = 1, new fraction = 0.760000000000
      Step  9: 0.760000000000 × 2 = 1.520000000000  -> bit = 1, new fraction = 0.520000000000
      Step 10: 0.520000000000 × 2 = 1.040000000000  -> bit = 1, new fraction = 0.040000000000
      Step 11: 0.040000000000 × 2 = 0.080000000000  -> bit = 0, new fraction = 0.080000000000
      Step 12: 0.080000000000 × 2 = 0.160000000000  -> bit = 0, new fraction = 0.160000000000
      Step 13: 0.160000000000 × 2 = 0.320000000000  -> bit = 0, new fraction = 0.320000000000
      Step 14: 0.320000000000 × 2 = 0.640000000000  -> bit = 0, new fraction = 0.640000000000
      Step 15: 0.640000000000 × 2 = 1.280000000000  -> bit = 1, new fraction = 0.280000000000
      Step 16: 0.280000000000 × 2 = 0.560000000000  -> bit = 0, new fraction = 0.560000000000

So the fractional part begins as:
      0.1111010111000010100011110101110000101000...

Therefore the full binary number is:
      1110.1111010111000010100011110101110000101000...

Step 4: Normalize the binary number
      1110.1111010111000010100011110101110000101000... = 1.1101111010111000010100011110101110000101000... × 2^3

Step 5: Determine the sign bit
      The number is positive, so sign bit = 0

Step 6: Determine the exponent bits
      Unbiased exponent = 3
      Bias for single precision = 127
      Stored exponent = 3 + 127 = 130
      130 decimal = 10000010 binary

Step 7: Determine the mantissa (fraction field)
      Take the bits after the leading 1 in the normalized form.

      First 23 bits before rounding:
      11011110101110000101000

      Next bit after those 23 bits:
      1

      Remaining bits after that:
      1110101110000101000

      Since the next bit is 1 and there are still non-zero bits after it, round up the 23-bit mantissa.

      Stored mantissa after rounding:
      11011110101110000101001

Step 8: Put the 32 bits together
      sign      exponent        mantissa
      0         10000010        11011110101110000101001

      Full 32-bit pattern:
      01000001011011110101110000101001

Step 9: Group into 4-bit nibbles to convert to hexadecimal
      0100 0001 0110 1111 0101 1100 0010 1001

      = 4 1 6 F 5 C 2 9
      = 0x416F5C29

So the 32-bit IEEE 754 float value for 14.96 °C is:
      0x416F5C29

E. Decode the IEEE 754 value back to a real number
--------------------------------------------------
Given hexadecimal float:
      0x416F5C29

Convert hex to binary:
      01000001011011110101110000101001

Split fields:
      sign bit     = 0
      exponent     = 10000010
      fraction     = 11011110101110000101001

1. Sign
      sign bit = 0 -> positive

2. Exponent
      exponent bits = 10000010 = 130 decimal
      unbiased exponent = 130 - 127 = 3

3. Significand
      Because this is a normalized number, prepend an implicit leading 1:
      1.11011110101110000101001

So the value is:
      (+1) × 1.11011110101110000101001_2 × 2^3

Shift the binary point right by 3 places:
      1110.11110101110000101001

This equals approximately:
      14.960000038147 °C

Rounded to 2 decimal places:
      14.96 °C

Final observation
-----------------
The ADC-to-temperature calculations produce values that are very close to the
displayed temperatures, and the small differences come from rounding. The
IEEE 754 conversions show that the decimal temperatures are not stored exactly
in binary, so the true stored float value is usually slightly above or below
the rounded decimal value shown on screen.
